# 休息气泡 + AI 提醒语 — 设计

日期：2026-10-07
状态：已通过设计评审，待写实现计划

## 意图

番茄钟进入**短休息 / 长休息**时，在 DSH 窗口内浮出一个圆形气泡，把正在工作的人从屏幕前拉走。气泡**持续整个休息时长**，内容里带一句提醒。

提醒句由**模型现场生成**，带当下状态（第几个番茄、今天已完成几个、当前时间），并每次轮换一个建议角度（喝水 / 远眺 / 走动 / 伸展 / 呼吸）。生成的目的是**不要变成壁纸**——同一句"站起来走两步"看三天就失效了。

**成功标准**：使用者真的离开电脑休息，而不是把气泡当装饰、或者顺手点掉继续干活。

**约束**：只能在 DSH 窗口内（插件无法创建原生窗口）；泡泡透明、不遮内容；一句话的成本和延迟必须可控。

### 为什么不做系统级通知

查过 DSH 暴露给插件的**全部服务目录**（宿主 + 客户端），命中 `notif|toast|alert|window|desktop|native|tray` 的只有 `shell` 和 `shellEnv`（bash 环境变量）。**DSH 没有任何通知 / 弹窗 / 原生窗口服务。**

浏览器原生的 `Notification` API 是唯一可能的系统级入口，但**它做不到"持续到休息结束"**——OS 通知是瞬时的，没有 API 能按住它 5 分钟。这条直接否掉了系统通知方案。

## 决策记录

| 议题 | 选定 | 否掉的选项及原因 |
|---|---|---|
| 提醒形态 | **应用内圆形气泡** | 上浮气泡流：持续动画会持续抢注意力。胶囊形：横着铺开会压住对话列中段，且失去"泡泡"的观感 |
| 气泡位置 | **中上方，视线自然落点** | 铺满全窗口：泡泡会从正在读的文字上穿过去。右侧竖带 / 从圆盘冒出：范围太小，容易被无视，仪式感弱 |
| 点掉之后 | **缩成 30px 小圆点挨着圆盘**，可再点开；休息期间不会真正消失 | 永久关闭：用户一旦习惯"关掉它"，之后每次都会条件反射关掉，比不做还糟 |
| 句子来源 | **模型现场生成** | 精选清单（20 句 + 状态模板）：零成本零延迟零失败，但几天后句子就都见过了。提前预生成：预生成的句子不可能知道休息那一刻的状态，与"带当下状态"直接冲突 |
| 句子与气泡的先后 | **气泡先出（默认句），AI 句到了再淡入替换** | 等句子好了一起出：气泡会迟到 1–3 秒，而休息开始那一下正是最该提醒的时刻 |
| 实现方案 | **宿主开只读路由 + 客户端拉一次**（无状态） | 加句子池 + 去重：宿主多一份持久化状态，且池里的旧句子不带当下状态，只能当兜底不能当主路 |

## 架构

插件目前是**纯客户端**的（宿主半是空的 `apply(){}`）。这个功能新增了插件的第一块宿主侧子系统。

```
休息开始（客户端 completePhase → phase = short | long）
  ├─ 立即渲染气泡，文案 = 默认句「站起来走两步」
  └─ fetch /pomodoro/tip?phase=short&round=3&done=7&angle=water&lang=zh
        └─ 宿主半：ctx.get('llm') → stream() → 攒 text-delta
              → 清洗 + 校验 → 200 {text} 或 204
  ├─ 200 → 新句子淡入替换默认句
  └─ 204 / 超时 / 网络错 → 保持默认句，不做任何提示
休息结束 → 气泡散掉；进行中的 fetch 一并 abort
```

**路由是无状态的**：宿主不记任何东西，状态全由客户端在 query 里给出。宿主半因此不需要持久化，也不需要和客户端共享生命周期。

**跨半调用用 HTTP 路由，不用 DSH 的 Remote/typert 机制**：后者是更正规的 RPC，但需要 typert 的生成式 schema 机制，这个手写、无构建步骤的插件用不了。

## 宿主半（`index.js`）

从空到约 120 行。注册一个精确路由：

```js
ctx.webServer.register({ kind: 'exact', path: '/pomodoro/tip', handler })
```

**`WebRoute.handler` 的签名有歧义**：inspect 输出把第二个参数解析成了 DSH 自己的 `ServerResponse`（`{ type: 'server-response', rpcId, result }`），但从 `IncomingMessage` 这个参数看，实际应当是 **Node 的 `http.ServerResponse`**（写响应头 + `end()`）。实现时按 Node 语义写，并验证。

处理顺序：

1. **服务缺席检查**：`ctx.get('llm')` 拿不到 → 直接 **204**。这是第一道降级，比超时早。
2. **同源检查**：`Origin` 存在且与请求 Host 不同源 → **204**。
   **`Origin` 缺席时放行**——同源 GET 通常不带 `Origin`，把它当跨站会误杀正常请求。跨站请求一定会带 `Origin`，所以这条仍然拦得住。
3. **模型选择**：走 `agentDefaultModel.currentSelection()` 拿当前 provider/model，**不硬编码**。
   **不传 `reasoningEffort`**（让适配器用它自己的默认），并设 `maxTokens: 60`。
   理由：本机的 desktop profile 配的是 `reasoningEffort: high`，显式抬推理档去写一句话是纯浪费，而且会拖长延迟。
4. **prompt**：system 约束输出形状（只输出一句话、12–20 字、不要引号、不要 emoji、不要说教、不要客套）；user 给状态（阶段 / 第几个番茄 / 今天已完成几个 / 当前时间）和这次的角度。
5. **清洗**：去掉引号、换行、开头的"好的，""没问题，"之类。
6. **校验**：长度不在 6–24 字（英文按词数换算）→ **204**。宁可回退，也不往气泡里塞一句怪话。
7. **超时 3.0 秒**（`AbortSignal.timeout`），并且**客户端断开时立刻 abort**，不让它在后台跑完。

`GenerateOptions.purpose` **不传**。该字段只接受 `'compaction' | 'session-title'`，没有给插件自用留位置——不传是合法的，但见"限制"。

## 客户端半（`client.js`）

- **气泡**：148px 圆形、磨砂半透明、停在中上方。内容三行：阶段名 / 剩余时间 / 一句提醒。
- **默认句**：中文「站起来走两步」；英文需要一条对应的 i18n 文案（`tip.fallback`），**不能把中文写死在代码里**——插件目前是中英双语的。
- **剩余时间**：跟随现有模型的秒级 tick 更新。
- **点掉**：缩成 30px 小圆点挨着圆盘，只留剩余时间；可以再点开。**休息期间不会真正消失。**
- **散掉**：休息结束（或用户切到专注）时自己消失。
- **角度轮换**：客户端持久化一个计数器，在 喝水 / 远眺 / 走动 / 伸展 / 呼吸 之间轮转，作为 query 参数发出——宿主保持无状态。
- **语言**：跟随界面语言发 `lang`，中英文的 prompt 和长度校验都不同。
- **指针穿透**：气泡只在自己那块矩形里接收点击，`shell.overlay` 浮层其余部分照旧穿透。
- **不抢焦点**：弹出时不夺取输入焦点。
- **减少动态效果**：`prefers-reduced-motion` 时不做淡入淡出与缩放动画。
- **新设置项**：一个"AI 生成提醒语"开关（默认开）。关掉就完全不发请求。

气泡独立于圆盘 / 卡片两种形态：无论当前是收起还是展开，休息开始都出气泡。

## 失败矩阵

| 情况 | 结果 |
|---|---|
| `ctx.get('llm')` 拿不到 | 204 → 默认句 |
| 没配模型 / 模型不可用 | 204 → 默认句 |
| 3 秒没生成完 | abort → 默认句 |
| 网络断 | fetch 失败 → 默认句 |
| 返回空 / 太长 / 太短 | 校验不过 → 204 → 默认句 |
| 返回里带引号换行 | 清洗掉，能救则救 |
| 用户在生成期间切走 | abort，不替换 |

**没有任何一种情况会让气泡变空或报错。** 最坏就是"这句话今天没换"，而默认句本来就是需求里要保留的。

## 限制与风险

1. **路由没有鉴权。** 它与界面同源。本地用没问题；如果把 `dsh web` 暴露到局域网，别人可以打这个路由**烧 token**。缓解：只接受 `Origin` 与请求 Host 同源的请求，跨站一律 204。这是缓解而非根治——同源的恶意脚本仍然能调用。
2. **借用了应用内部的 API。** `GenerateOptions.purpose` 的取值只有 `compaction | session-title`，没有为插件自留位置。不传就合法，但说明这个接口的设计意图是应用内部使用。**将来 DSH 改这个接口，插件可能会坏。** 这是本方案唯一的长期风险。
3. **模型选择跟随用户配置**，因此成本和延迟不完全由插件决定。`maxTokens: 60` 和 3 秒超时是硬上限。

## 隐私

发给模型的**只有数字**：阶段、第几个番茄、今天已完成几个、当前角度、语言。**不含任何对话内容、文件内容或工作区路径。**

## 不做的事（YAGNI）

- 不做系统级通知 / 桌面悬浮窗（API 不存在，且做不到"持续到休息结束"）
- 不做句子池持久化与去重
- 不做"每日一句"之类的额外功能
- 不做气泡位置可配置（先固定中上方，用起来不合适再说）
